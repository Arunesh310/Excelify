## Problem Statement

Excelify ships five browser-local spreadsheet tools with strong SEO, but sessions are **one-shot**: users upload, fix, export, and leave. There is no sticky workflow, no clear upgrade path, and no feature that Excel power users cannot approximate with VLOOKUP plus manual cleanup. Scaling requires a **named job** ("reconcile two exports") completed faster and more safely than the status quo, without abandoning the privacy story.

## Demand Evidence

- **Implicit:** Product already narrowed to clean / compare / match / ageing — the highest-intent SEO pages target compare, match, and duplicate removal (see `src/lib/seo/pages.ts`).
- **Behavioral proxy (to validate):** Repeat visits to `/app/match` and `/app/compare`, export clicks, and search queries on the app dashboard (`ToolSearch`).
- **Gap:** No logged-in cohort yet (`AUTH_ENABLED` false); demand proof must come from analytics and 5–10 user interviews with ops/finance admins who reconcile vendor or payroll files weekly.

## Status Quo

Target user runs two exports from ERP, bank, or SaaS → opens Excel → trims spaces, removes dupes → VLOOKUP/XLOOKUP → filters `#N/A` → sends CSV to manager. Pain: **30–90 minutes**, error-prone keys, no audit trail, fear of emailing sensitive files.

## Target User & Narrowest Wedge

**Who:** Ops or finance analyst at a 20–500 person company; reconciles **two flat files weekly** (same keys, messy text).

**Wedge (smallest paid-worthy version):**  
*"Upload base + lookup → auto-clean keys → match with preview of failures → export reconciled file — all in browser, no account."*

Phase **A** makes the wedge **reliable** (limits, pipeline, exports, discoverability). Phase **B** makes it **better than Excel** (fuzzy + multi-key + audit stats + saved mappings).

## Constraints

- Processing stays **client-side** for free tier (marketing promise).
- No fake history or auth until presets prove repeat use.
- Reuse `parser`, `cleaner`, `comparer`, `matcher`, `ageing`, `export` — no new backend for Phase A/B.
- EvenTab / `splitfair` is **out of scope** for this design.

## Premises (challenged)

| Premise | Verdict |
|--------|---------|
| "More single-purpose tools = growth" | **Partially false** — SEO helps acquisition; retention needs **one pipeline**. |
| "Users want accounts early" | **Unproven** — localStorage presets first. |
| "Fuzzy match is mandatory day one" | **False for v1 of B** — ship multi-key + audit first; fuzzy second slice. |
| "Large files must work in free tier" | **False** — explicit limits + Pro later. |

## Approaches Considered

### Approach A: Toolbox expansion (many new tools)

Add split-column, filter, merge, etc. Maximizes SEO surface; weak retention story.

### Approach B: Platform first (auth, history, billing)

Enables monetization but repeats half-built auth pattern; high complexity before repeat-use proof.

### Approach C: A+B Reconciliation program (**chosen**)

**A — Polish & guardrails:** CSV export, file/row limits, clean→match handoff, preview in nav + SEO, localStorage presets (column maps), dedupe-by-key mode.  
**B — Reconciliation depth:** multi-key match, pre-export match audit (% unmatched, duplicate lookup warnings), optional fuzzy match (normalized + Levenshtein threshold).

**Rationale:** Composes existing engines; one narrative for landing, SEO, and product; clear Pro boundary (limits + fuzzy + batch later).

## Recommended Approach

Ship **Phase A** in 2–3 vertical slices, then **Phase B** in 2 slices. Do not start auth/history until week-4 retention metric moves (see Success Criteria).

## Open Questions

1. Default file size cap for free tier (10 MB vs 25 MB)?
2. Fuzzy match default: off vs "suggest near matches" panel?
3. Handoff state: `sessionStorage` only vs optional `localStorage` "resume last job"?

## Success Criteria

| Metric | Target (90 days post Phase A) |
|--------|-------------------------------|
| Match tool export rate | +25% vs baseline |
| Return within 7 days | ≥15% of export users (cookie-less proxy: localStorage preset re-use) |
| Support burden | Zero "browser crashed" without user-visible limit message |
| Phase B | ≥10% of match sessions enable multi-key or fuzzy |

## Implementation backlog (input to eng review)

### Phase A

1. **A1 Guardrails** — max bytes, max rows, friendly errors in `parseWorkbookFile`.
2. **A2 Export** — `exportToCsv()` alongside XLSX; use in all tool result pages.
3. **A3 Pipeline** — `ReconciliationSession` in sessionStorage: cleaned base → match with lookup file.
4. **A4 Discoverability** — preview in sidebar; `/tools/excel-preview` SEO entry.
5. **A5 Presets** — save/load match column mapping + clean options (localStorage).
6. **A6 Dedupe by key** — `cleanWorksheet` option: dedupe on selected column only.

### Phase B

1. **B1 Multi-key match** — composite key in `matcher.ts` (order-stable join).
2. **B2 Match audit panel** — stats: matched %, blank keys, duplicate lookup keys (surface existing `detectDuplicateLookupEntries`).
3. **B3 Fuzzy match** — optional tier: normalize + Jaro-Winkler or Levenshtein threshold; cap comparisons for perf.
4. **B4 Worker** — move parse + match off main thread for files under cap.
