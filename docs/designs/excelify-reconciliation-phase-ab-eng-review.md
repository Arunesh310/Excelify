## Section 2: Data & state

**Pipeline handoff schema (v1):**

```ts
interface ReconciliationSessionV1 {
  version: 1;
  createdAt: string;
  base: { fileName: string; sheetName: string; headers: string[]; rows: string[][] };
  cleanOptions?: CleaningOptions;
  matchConfig?: Partial<MatchInput>;
}
```

- Store **rows** in sessionStorage only if under row cap; else store hash + prompt re-upload (CEO: prefer re-upload over IndexedDB for v1).
- **Presets (A5):** separate localStorage key `excelify.presets.v1` — never store full files, only column names + options.

## Section 3: Match engine changes (B)

**B1 Multi-key:** Extend `MatchInput` with `baseKeyColumns: string[]` and `lookupKeyColumns: string[]` (same length). Composite key: `cols.map(normalize).join("\u0001")`. Keep backward compat with single `baseKeyColumn`.

**B2 Audit:** Reuse `detectDuplicateLookupEntries`; add `summarizeMatchResult(result): { matchedPct, unmatchedRows, blankBaseKeys, blankLookupKeys }`.

**B3 Fuzzy:** New module `fuzzy-match.ts` — only invoked when `fuzzyEnabled: true` and `threshold` set. Algorithm: normalize (trim, lower, collapse spaces); compare with Jaro-Winkler; **cap** candidate lookups per base row (e.g. 500) to avoid O(n²). Show match method column in output (`exact` | `fuzzy` | `none`).

**Tests:** Extend `scripts/test-matcher.ts` → migrate to `src/lib/excel/matcher.test.ts` (Vitest).

## Section 7: Failure modes & rescue

| Mode | Detection | Rescue |
|------|-----------|--------|
| sessionStorage quota | try/catch on setItem | Trim rows or show "file too large for pipeline" |
| Header drift base vs lookup | audit blank keys | UI link back to clean |
| Fuzzy wrong link | confidence < threshold | Export with review flag column |

## Section 8: Security

- Client-only: no SSRF/server upload.
- xlsx parse: keep dependency pinned; no macro execution path.
- Presets: JSON.parse with schema validation (zod optional; manual check OK for v1).

## Section 9: Performance

- Full-grid match is O(base × lookup) for fuzzy worst case — **must** cap.
- Consider indexing lookup map only (already Map-based) — OK for exact path.
